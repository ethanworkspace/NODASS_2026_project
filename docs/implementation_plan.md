# 實作計畫

## 第 1 階段：資料基礎建置

- 建立海保署水質 CSV 讀取流程。
- 建立 CWA、IHMT、NAMR、WRA 海氣象 CSV 讀取流程。
- 正確處理原始 CSV 前三列：
  - 中文欄位名稱
  - 英文欄位名稱
  - 單位
- 建立統一測站資料，包含測站編號、名稱、資料來源、站點類型、經度與緯度。
- 將標準化後的資料輸出到 `data/processed`。

## 第 2 階段：異常偵測

- 先以測站層級的統計基準值建立第一版異常偵測。
- 偵測項目包含：
  - 葉綠素 a
  - 氨氮
  - 硝酸鹽氮
  - 亞硝酸鹽氮
  - 正磷酸鹽
  - 矽酸鹽
  - 懸浮固體
  - 鎘、鉻、銅、鋅、鉛、汞
- 將異常事件儲存為 `anomaly_events`。
- 當歷史資料足夠時，再加入季節性基準線。

## 第 3 階段：72 小時時空事件窗

- 對每個異常事件，擷取事件前後 72 小時觀測資料。
- 依距離與時間覆蓋率配對鄰近海氣象站。
- 彙整主導風向、主導流向、流速與潮位變化。
- 只保留上風、上游流向或 72 小時內可達的測站與來源區。

## 第 4 階段：候選來源資料庫

- 補入外部河口與流域資料。
- 補入污染源資料：
  - 污水處理廠
  - 工業區
  - 港口與港區
  - 養殖與農業逕流區
  - 放流口
- 為每種來源類型建立可能污染物對照。

## 第 5 階段：來源排序

- 第一版先實作透明的規則式評分。
- 對每個候選來源計算：
  - 距離分數
  - 上風一致性
  - 上游流向一致性
  - 72 小時可達性
  - 污染物與來源類型吻合度
  - 降雨與河川流量支持度
- MVP 穩定後，加入貝氏網路後驗機率。
- 取得事件標籤與排放紀錄後，再加入因果推論。

## 第 6 階段：AI Agent 與事件報告

- 建立事件監測 Agent，自動執行完整流程。
- 每個異常事件產生一份 Markdown 報告。
- 報告內容包含：
  - 異常測站與污染物
  - 72 小時風、流、潮摘要
  - 候選來源排序
  - 信心等級
  - 仍缺少的佐證資料

## 第 7 階段：儀表板與 API

- 建立以地圖為核心的中文儀表板：
  - 異常測站
  - 風向與流向向量
  - 鄰近河口
  - 候選來源區
  - 生態敏感區
- 建立測站、事件、來源與報告查詢 API。
