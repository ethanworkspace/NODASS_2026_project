# React 前端架構

## 目標

前端以 React 呈現 NODASS 初版系統的互動式工作台，讓使用者可以篩選異常事件、查看候選污染來源排序、檢視 72 小時時空一致性條件，並確認仍需自行申請或補入的 API 與資料。

## 部署方式

目前採用靜態部署：

- `dashboard/index.html`：React 互動前端原始頁面。
- `dashboard/system_data.json`：本機資料管線產生的前端資料。
- `dist/index.html`：部署用前端頁面。
- `dist/data/system_data.json`：部署用資料檔。

此方式不需要後端常駐服務，也不會把大型原始資料上傳到部署環境。

## React 狀態設計

主要狀態：

- `activeTab`：目前頁籤，包含總覽、異常事件、來源追蹤、時空一致性、資料補齊。
- `query`：事件搜尋文字。
- `group`：污染物群組篩選。
- `confidence`：來源推估信心篩選。
- `selectedId`：目前選取的異常事件。
- `data`：由 `system_data.json` 載入的系統運算資料。

## 資料流

1. Python 管線讀取原始資料並產生：
   - 異常事件
   - 72 小時事件窗
   - 候選來源
   - 來源排序結果
   - 雨量站串接狀態
2. 管線輸出 `dashboard/system_data.json`。
3. React 前端載入 JSON。
4. 使用者在前端切換頁籤、篩選事件、點選事件。
5. 前端即時更新事件詳情、來源排序與時空條件。

## 時空一致性呈現

前端會顯示每個事件的：

- 事件窗開始與結束時間。
- 事件窗內可用海氣象資料筆數。
- 主導風向。
- 主導流向。
- 平均流速。
- 潮差。
- 最近雨量站與雨量資料狀態。

來源排序僅顯示後端管線已通過以下條件之一的候選來源：

- 72 小時內依平均流速可達。
- 來源位於上風方向。
- 來源位於上游流向可達方向。

## 後續可升級方向

- 改為 Vite/React 專案並加入正式打包流程。
- 使用地圖套件呈現真實座標點位。
- 加入 API 後端，讓使用者上傳新資料後即時重新分析。
- 加入登入與權限管理，區分公開展示資料與內部原始資料。
